# Portable Dream Loop for Slime VFX

This is the project's portable workflow summary, based on the Dream Loop process previously used in this conversation. It is not a claim that a global skill/plugin has been installed in a new environment.

1. Lock the user-supplied target and latest written corrections. Latest corrections override older imagery.
2. Implement the baseline. Render actual game shaders/geometry from the gameplay camera.
3. Inspect saved images and consecutive frames in `/review/index.html`, then inspect motion. Check combined and isolated layers.
4. Ask an independent reviewer with fresh context when available. Supply target, latest actual frames, previous findings, and exact current user brief.
5. Rubric: Composition 0–3 (camera, silhouette, layout), Lighting 0–3 (palette, light, contrast), Materials 0–3 (expected shape/surface/translucency), Details 0–1 (cleanup/finishing).
6. Score honestly. Compilation, unique file hashes, and test success do not grant visual acceptance. Do not infer user approval from an internal score.
7. At >=8, visual threshold is met; device FPS is a separate gate. No FPS measurement means unverified, not 60fps.
8. Same gap in two rounds or no full point improvement over two rounds: stop incremental nudges and rethink architecture. If that also stalls, show the actual result and seek targeted user feedback instead of inventing a pass.
9. Preserve experimental work under ignored `.dream-loop/`. Keep useful references and actual review outputs in versioned `public/review/`.

Required current smoke shape: broad grounded base, upward taper into thin curved anime/manga crests, clockwise sweep followed by stretch/thin/peel/dissolve. Do not reintroduce puff spheres just because an older target shows rounded billows.
